Documentation

Operator guides for a fleet of mining turtles on All the Mods 10 — running a quarry from a control station, cutting corridors with a single turtle, and the protocol underneath it all.

Modpack: All the Mods 10 MC: 1.21.1 · NeoForge Mod: CC:Tweaked

1Guides

The control.lua Station

control.html

Set up and command a fleet of 2–5 mining turtles from one control computer — on-screen job wizard, live dashboard, fleet-wide keyboard controls, and crash-safe resume.

Read it when you want to run a quarry with several turtles from one computer + monitor.

The dig Program

dig.html

Send one turtle down a straight corridor of any size — torch-lit, its floor patched over caves and lava, its loot streamed into an Ender Chest — and it walks itself back to the mouth.

Read it when you want one standalone turtle to cut a corridor. No modem required.

The strip Program

strip.html

Send one turtle down a spine tunnel that throws off ribs left and right at a fixed spacing — the classic strip mine — chasing down every ore vein it uncovers along the way.

Read it when you want one standalone turtle to run a strip mine that also mines the ore it exposes.

How fleet talks to control

fleet-and-control.html

The ccfleet rednet protocol: the six message types, who sends what to whom, and a full run traced message by message.

Read it when you're changing comms.lua, coordinator.lua or worker.lua — or debugging a fleet that won't start.
Start here

New to the project? Read control.html first — it's the operator guide. fleet-and-control.html is its internals companion.

2Archived plans

plans/ holds completed build plans, kept for their design rationale. They describe work that is already finished and are not current documentation — the code and its tests are the source of truth.

  • plans/quarry-plan.md — how quarry.lua was designed and built: box geometry, the layer-flip rule, and the return path.
  • plans/branch-plan.md — how branch.lua was designed and built: why ribs are cut mid-sweep, the vein depth-first search, and the onProgress excursion contract it leans on.

3Adding a guide

Every page links one shared stylesheet, style.css, then adds only its own widgets inline:

<link rel="stylesheet" href="style.css">
<style>
  /* only this page's own widgets go here */
</style>

The conventions that keep the set consistent — file naming, the <title> pattern, the --wrap-max override and the single 640px breakpoint — are written up in README.md.
